# Pitoa Strategy Hub

Pitoa is a Rails 8 application that showcases a curated set of 20 marketplace strategy frameworks used inside Willit. It ships with an interactive walkthrough, KPI dashboards, and impact storytelling pages powered by ViewComponent, Stimulus, and TailwindCSS. This repository also contains the static assets that back the public microsite in `docs/`, making it a good reference app for Rails + ViewComponent front-ends.

## Features
- Curated toolkit data lives in `config/business_tools.yml`, making it easy to extend without touching Ruby code.
- Modular UI composed with ViewComponent (`ToolCardComponent`, `MetricDialComponent`, `TimelineGateComponent`) and Stimulus controllers for client-side polish.
- Tailwind 4/Turbo stack with JS & CSS bundling already wired up through esbuild and the new `@tailwindcss/cli`.
- Ready-to-ship Dockerfile, Kamal config, and GitHub Pages–friendly `/docs` export for hosting demos.
- Batteries-included developer experience through `bin/dev` (Rails server, JS bundler, Tailwind watcher) and `bin/setup`.

## Tech Stack
- Ruby 3.3.9 / Rails 8.0 (Propshaft, ViewComponent, Turbo, Stimulus)
- SQLite for development, Solid Queue/Cache/Cable optional adapters enabled
- Tailwind CSS 4 + esbuild via `jsbundling-rails` and `cssbundling-rails`
- Node.js 24.10.0 (see `.node-version`) with Corepack/Yarn
- Foreman + Procfile.dev for local process orchestration

## Getting Started

### Prerequisites
- Ruby 3.3.9 (managed via `rbenv`, `asdf`, or `chruby`)
- Node.js 24.10.0 with Corepack (`corepack enable`)
- SQLite 3.32+ and bundler ≥ 2.7
- Yarn (installed via Corepack) and a working C toolchain for native gems

### Installation
```bash
git clone https://github.com/rholappa/pitoa.git
cd pitoa
bin/setup           # installs gems, JS deps, prepares DB, starts bin/dev unless --skip-server
```

`bin/setup` is idempotent and safe to rerun whenever dependencies change. It installs gems, runs `yarn install`, prepares the SQLite databases in `storage/`, and clears temp/log files.

### Running the app
- `bin/dev` – starts Rails (`bin/rails server`), `yarn build --watch`, and `yarn build:css --watch` via Foreman.
- `bin/rails s` – run the server alone if you prefer to build assets manually.
- `yarn build` / `yarn build:css` – one-off JS/CSS builds for production assets.

Visit http://localhost:3000 to browse the strategy hub once the dev server is running.

## Tests & Quality Gates
- `bin/rails test` – run the full Minitest suite.
- `bin/rails test:system` – execute system tests in a headless browser.
- `bundle exec rubocop` – Ruby style checks (provided by `rubocop-rails-omakase`).
- `bundle exec brakeman` – security scan for common Rails vulnerabilities.

Please run the tests and at least RuboCop before opening a pull request.

## Project Structure Highlights
- `app/components/` – ViewComponent classes and templates that power the cards, dials, and timeline gates.
- `app/javascript/controllers/` – Stimulus controllers (accordion toggles, KPI animations) registered via `app/javascript/controllers/index.js`.
- `config/business_tools.yml` – Source of truth for all tools that appear in the walkthrough and docs.
- `docs/` – Pre-rendered static site used for GitHub Pages or marketing demos. Update by running the asset builds before publishing.
- `.kamal/` + `Dockerfile` – Infrastructure definitions for containerized deploys.

## Customising Content
1. Update `config/business_tools.yml` with additional tools, categories, or CTAs.
2. Adjust the layouts in `app/views/walkthrough/*.html.erb` or extend the component set.
3. Re-run `bin/dev` (or rebuild assets) to refresh the UI. The docs site can be regenerated by copying the latest `app/assets/builds` output into `docs/assets`.

## Deployment Notes
- Docker: `docker build -t pitoa .` creates a production image that runs via `./bin/rails server`.
- Kamal: configure `.kamal/config.yml` with your registry and hosts, then deploy via `bundle exec kamal deploy`.
- Static demo: serve the `docs/` folder (e.g., on GitHub Pages) for a zero-backend walkthrough.
